# Codex Partner 卡顿修复实测（2026-10-19）

部署位置：`/root/Codex-Partner`，端口 `8787`。

## 原因与修改

1. 本地 Codex 数据库约 11,325 条线程记录，Partner 约 5,000 个会话。内部子线程等记录不会出现在 `thread/list` 中，却不断触发全量同步。现在记录已检查的线程，并将自动全量同步限制为最多每 60 秒一次；仍每 2 秒检查未导入会话的活动 writer，以继续发现正在运行的 exec 会话。显式同步仍可执行。
2. 会话列表及 overview WebSocket 原来携带所有会话的完整 prompt；数据库中 prompt 合计约 174 MB（按 SQLite 字符数估算）。现在列表仅查询前 512 个字符，完整 prompt 保留在数据库和具体会话接口中。侧栏搜索范围相应变为提示词摘要、完整名称、目标和工作目录。
3. overview 原来逐会话创建数据库查询连接，单次分析耗时 3.69 秒。现在批量查询，并增加 `tasks(codex_session_id)` 索引。同步逐行让出事件循环，跳过无变化的任务更新和原生模型写入。
4. 侧栏原来每次状态变化重新创建约 5,000 张卡片和日期格式化器。现在复用未变化的 DOM 卡片及日期格式化器，并消除 overview 合并中的嵌套查找。

## 第二轮：滚动、输入和会话切换（同日）

针对“仍不够流畅”继续优化，已部署到当前服务。

- 侧栏使用固定行高的虚拟列表，只渲染视口及缓冲区；5,026 个会话在 1440×1000 视口中只生成 27 张卡片。支持滚动到最后一条、键盘 Home/End/上下移动和当前会话定位。
- 新增 `GET /api/tasks?compact=true` 和 compact overview 快照，仅传侧栏元数据。完整提示词、目标及配置由具体会话接口加载；完整目标不会被摘要覆盖。列表搜索移到后台，支持匹配完整提示词、目标、名称和工作目录，并对输入做 150 毫秒防抖及旧请求取消。
- 非首屏必需的 Skills、记忆及命令加载不再阻塞打开会话。
- 最近聊天页返回可继续翻页的 native cursor，不再每次切换后自动读取整段原生历史；无持久化消息的历史会话仍会补载。向上翻页保留完整历史访问能力。
- 历史文件轮询在一个工作线程中批量 stat，仅调度新文件、变化文件及活动会话。保持文件截断检测、活动 writer 检查及失效路径清理。运行中任务归属检查仅读取三个必要字段，避免每两秒读入全部提示词。

上线后的 20 次完整列表请求：中位数 383.78 毫秒，P95 1,121.61 毫秒，最大 1,650.10 毫秒。重启后的早期测试出现一次 6.657 秒请求，因此不能声称所有请求均低于一秒。40 次存活探测中位数 2.35 毫秒、P95 251.4 毫秒、最大 530.14 毫秒。繁忙时后端仍有长尾；服务在并行处理活动任务时实测 CPU 约 85%，没有宣称 CPU 问题已消失。

浏览器真实连接验证：全量列表底部可达；键盘 Home 可回首条；`torchada` 搜索返回 2,254 条匹配且仍只渲染 27 张卡片；两个会话均能输入、收到聊天事件，连接状态为 live；脚本错误为 0。历史翻页实请求返回 120 条更早记录，用时 682 毫秒，并继续提供下一页游标。

Python 回归：291 passed、121 subtests passed。新增覆盖紧凑列表不泄漏完整详情、完整提示词搜索、文件变化/截断/活动状态筛选、最近页向更早历史翻页。原有 5 个网页任务最终全部为 running 且 last_error 为空；测试期间其中一个曾因上游模型容量不足自动重试，随后恢复。
